# Almanac Study — Source-to-Family Communication Gate v1.0
**Date:** 22 November 2026
**Status:** Proposed operational rule for owner review. This is not an approved public brand change, and no publication is authorized by this document.

## Why this exists
Almanac posts must come from the established project context, updated principles and verified learner/product evidence — never from generic social post prompts, unrelated lifestyle themes or an imagined product demonstration. In particular: **learner need -> source/evidence -> defined benefit -> editorial family -> script -> visual -> review -> publication -> measurement**. The family is chosen *after* the reason for the post is known.

## Mandatory sources to consult on every production run
Read the currently updated versions in this order, and record the exact repo ref/commit and date used:
1. `.agents/skills/almanac-campaigns/SKILL.md`; `campaigns/README.md`; `campaigns/registry.yaml`
2. `campaigns/ALMANAC_LEARNING_PHILOSOPHY_PROPOSAL.md` (a **working proposal**, NOT the approved public brand promise)
3. `campaigns/EDITORIAL_SERIES_V1.md`; `campaigns/visual-system.md`; the current sprint/experiment records
4. The relevant campaign `brief.md`, `product-origin.md`, queue, topic map and original reviewable learning assets
5. Current product implementation/specs, permissions and release/checkout documents; the latest observed audience reactions and verified publication metrics

If sources are missing, label **MISSING/UNVERIFIED**, select a safe source-independent family only if it delivers real value, or HOLD the piece. Never reconstruct missing source information as fact.

## The six approved-for-planning editorial families
| Family | Communication job | Evidence needed | Primary action |
| --- | --- | --- | --- |
| **ONE IDEA, CLEARER** | Show one precise conceptual distinction | Topic-matched, reviewed explanation/source | Understand, explain or save |
| **THINK BEFORE YOU TURN** | Prompt original practice, followed by full reasoning | Original question, verified rationale, clinical review where applicable | Attempt then check the explanation |
| **THE STUDY DESK** | Apply a practical learning habit or original editorial reflection | Reviewed original writing that produces a usable action | Try one specific method |
| **INSIDE ALMANAC** | Demonstrate actual Almanac learning materials, not a hypothetical mock | Genuine redacted reviewed item, permission and actual release status | Inquire about the verified resource |
| **YOUR NEXT STEP** | Learn what the student is preparing for and where they are stuck | Real audience-relevant question with privacy-safe reply route | Voluntary needs response |
| **THE RETURN VISIT** | Return to the specific earlier idea/question and correct or deepen it | Exact preceding post and approved follow-up explanation | Revisit, self-correct, continue |

These six families define what we communicate to prospects. Product conversion must follow real instructional value and honest availability, not unsupported scarcity or marketing-first filler.

## Every post must have a family/source manifest before a pixel is generated
- **Campaign ID / post ID / candidate date / target channel**
- **Exact family:** one primary family (optional secondary only if justified); series purpose and place in the learner journey
- **Audience and actual learner need:** cite current campaign brief or verified audience signal
- **Learning source:** exact repo path/ref/asset and approval stage; quote what is **verified**, **user-reported** and **unknown**
- **One self-contained educational benefit:** what the audience can learn/do from the free post
- **Primary CTA:** one of learn/save, meaningful response or verified resource inquiry; approved destination only
- **Product claim ledger:** every claim tied to inspected product/code evidence, with rights and reviewer sign-off if needed
- **Visual recipe:** matching layout defined in the editorial family; recognized Almanac identity; 1080×1350 feed or 1080×1920 Story with phone-readable text and accessibility copy
- **Release gates and status:** owner approval, topic/clinical review, rights, source authenticity, asset readiness, audience privacy, valid payment/fulfilment route
- **Measure:** the specific meaningful action and 24h/72h/7d review (when observable)
- **Versioned provenance:** link campaign brief, creative, file version, approved caption, publishing URL *only when actually published*

If any mandatory source-backed clinical or product claim fails, **BLOCKED** is mandatory. Creative quality never substitutes for evidence.

## Prospect communication rule
Each post should stand on its own, then invite *one* sensible next step. Stage-specific progression:
**Teach/Practise -> identify learner need -> show genuine, reviewed relevant learning material -> qualify a request -> authorized offer -> useful follow-up.**
A student asking for NR 601 can be directed to `Almanacstudy.support@gmail.com` with subject `NR 601 midterm`, but claims of availability, free access, exact pack contents, payment or guaranteed outcomes must wait for verification. Other subjects can be named in an inquiry; support and availability must not be presumed.

## Acceptance test
A reviewer should be able to answer in under one minute: **Which family? Which learner need? Which source? Which verified benefit? Which one next action? Which approval status?** If any answer is absent, the piece returns to DRAFT or BLOCKED — it does not enter the publishing queue.

## Change control
Family architecture and underlying philosophy files are not silently rewritten by this gate. This document proposes a stricter production check in the existing versioned workflow. No Facebook post, email, ad or payment action is authorized here.
