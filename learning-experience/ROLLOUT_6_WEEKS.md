# Six-week starting rollout + scaling gates
**These are planning horizons, not a promise of unattended execution or launch dates.** The user can accelerate/slow per team capacity; actual progress must be checked and reported. Start with existing Almanac media offers and pilot content; do not rebrand or replace homepage immediately.

## Self-service as a cross-cutting workstream
- **Start with the actual package builder.** Its existing packaged scope, start preferences, delivery and priced extras provide the pricing skeleton; do not create a second contradictory checkout.
- **Week 1–2:** validate local configurator prototype, transparent quote limits, study objective and learning preference prompts; wire a private learner-path prototype only after source and entitlement checks. No billing.
- **Week 3–4:** test choice of start modes and session lengths against one fixed reviewed learning objective; inspect comprehension, task completion, option fatigue and meaningful override, preserving FSRS.
- **Week 5–6:** if safe, pilot persistent changeable study preferences and a compact 'Today' choice gateway; validate server-side permissions, offline recovery, no price effect and exact-version course release.
- **Scaling:** separate already-released self-study catalogs from newly commissioned bespoke courses. Existing catalog item pricing remains undefined until approved, and music/stories/games require explicit rights, educational utility and commercial support before standalone SKUs.
- **Fundamental distinction:** learners control how they experience entitled material; Almanac controls verified objectives, factual integrity, entitlement and price of new production.

## Preflight: first 48h of active work — content and channel audit
- Inventory actual program content, products and 17-reported NR 601 source items if available; reconcile distinct NR 601 vs NUR-635 vs current pathophysiology pilot.
- Inspect current MP4/VTT/poster configuration and which existing videos are real vs placeholder; catalog PPTX, notes, audio, NotebookLM exports and supported delivery paths.
- Record each public account/platform access and permissions: Facebook page, Instagram, TikTok, YouTube, email / WhatsApp consent, website content approval, no ad spend authorization by default.
- Identify one rights-cleared, non-sensitive pilot learning objective, ideally independent learning methodology if the NR 601 collection is unavailable.
**Deliverable:** honest inventory + owners + blockers. **Gate:** one verified, reusable explanation with assessment and source license.

## Phase 1 — weeks 1–2: reliable minimum multimedia
**Public:** publish (on approval) Explain Test carousel; needs-prompt and quote; prepare one fully captioned microvideo and audio companion based on the same reviewed idea, each useful alone. Record post URLs/ages and inquiries.
**Workspace:** implement asset manifest schema *without* changing live checkout; build a canonical objective-to-asset mapping for one test module; make existing narrated video/slide experience inspectable and accessible; produce one genuine lesson pack with text, slide summary, short audio, short video, original question and explanatory feedback.
**Experimental low-fi:** one static three-choice story in PPTX/PDF with a debrief; one sortable-card quiz using existing web forms/HTML, not a new platform engine.
**Gate:** all files actually playable and accessible, subject/right reviewed, one objective coherent across formats, no broken video fallbacks, exact-version approvals. **Stop:** bad answers or unlicensed third-party material.

## Phase 2 — weeks 3–4: responses and first limited pilots
**Public:** trial story-led 'what would you do?' original scenario and a question+answer follow-up; consider TikTok/YouTube Shorts only if platform and content approvals exist. Test whether lesson posts yield meaningful attempts vs views.
**Workspace:** prototype an accessible branching story with 2–3 meaningful choices and feedback; implement a keyboard/touch/tap alternative to drag-and-drop; track objective-level attempts with no raw private personal data exposed to marketing.
**Novelty experiment:** optional 15–30-second *original* sung mnemonic for a small, stable low-stakes sequence, paired with identical spoken/text cue; no automatic playlist.
**Gate:** prototype users understand and correctly answer a delayed transfer item at least as often as with existing text-based review, and no major accessibility defect. Otherwise rework or discard.

## Phase 3 — weeks 5–6: productize only the winners
**Public:** organize successful educational formats into repeatable series; release real evidence-based previews only from accessible, rights-cleared products; build opt-in digest and reliable reply templates.
**Workspace:** promote the best story/game interaction to a small reviewed module; add consistent media picker to a pilot course if feasible; track whether students can navigate from video/audio/deck to meaningful practice.
**Business:** validate requested formats, production time per item, review cost, learner satisfaction, first valid orders if checkout authorized, and recurring usage.
**Gate:** no medium is sold as a package feature until reproducible capacity, QA, accessible delivery, rights and scope are demonstrated.

## Scaling horizon: months 2–6 (conditional, not committed launch)
1. **Canonical content schema:** objectives, approved claims, sources, references, course topics, versioned content items. Populate an actual rights-cleared library.
2. **Modular production:** build script -> slides -> narration -> caption/video -> practice -> export with version and source hashes; human signoffs and review queue.
3. **Media delivery:** reliable CDN/object storage, manifest-backed playlists, text-first fallback, bandwidth variants, analytics and signed entitlements; tests for lower-speed networks.
4. **Responsive selection:** use per-objective performance, self-selected preferred start modes, review history, opt-outs; test minimal next-step recommendation rules before introducing an unverified AI tutor.
5. **Stories/games:** reusable scenario authoring blocks and small assessment games in the course player, with learning-transfer A/B or within-person comparisons.
6. **Music:** optional licensed original mnemonic library *only* if experimental delayed recall and satisfaction outcomes justify the cost. Do not prioritize heavy music generation over feedback and practice.
7. **Team capacity:** specialist reviewer scheduling, content QA queue, asset provenance, rights licensing, accessible templates, complaint/correction handling.
8. **Revenue:** consider format-specific enhancements only after willingness to pay and actual fulfillment costs are established, avoiding false 'unlimited on-demand' promises.

## Prioritization table
| Work | Now | 3–6 weeks | Later | Owner decision |
|---|:---:|:---:|:---:|---|
| Text, slides/PPTX, narrated videos, transcript/audio and original practice | ✓ | improve and connect | automate verified production | approve actual asset inventory |
| Public short videos, carousels, needs prompts | ✓ | measure and repurpose | expand platforms | approve posts/accounts |

| Story case in PowerPoint or PDF | pilot | interactive narrative prototype | native story authoring engine | choose candidate learning objective |

| Multi-channel publishing automation, ads and paid checkout | no default autonomy | approved workflow only | policy/permission-gated | explicit authority + provider approval |

## Expected products at end of initial rollout (only if acceptance gates met)
- One fully QA'd learning-object portfolio with text + PPTX + MP4/VTT + MP3/transcript + original retrieval/rationale.
- One short public microvideo + carousel + story/quiz link derived from it, with published metrics if approved.
- One comparative optional mnemonic pilot; one simple game/story pilot with reflection and outcome measure.
- Reusable templates, reviewed media manifest, source and rights registry and cost-per-unit production log.
- Clear recommendation to promote, revise or discontinue each experimental modality.

## Stop-the-line triggers
Any clinical inaccuracies, unclear reuse rights, inaccessible essential activity, paid commitments not fulfillable, corrupted progress, unapproved provider checkout or unstable learner data handling.
